# Agent security

Rabt's agents (triage, navigator, comms, reassurance, claims) run inside the orchestrator. The insurer is a **separate agent** reached over A2A. The controls below are in the code and covered by tests. They are mapped to the OWASP LLM / agentic risks.

| Risk | Control | Code | Test |
|---|---|---|---|
| Prompt injection (direct and indirect) | Deny-list (EN + AR), then Azure Prompt Shields on user text **and** retrieved documents for untrusted-input tasks. Fails closed when Shields is configured but errors. | `agents/common/injection.py`, `agents/common/llm_client.py` | `test_ai_core.py` |
| Sensitive data to the model | PII scrubbed before every model call. The regex pass handles Emirates ID, NRIC, emails, UAE/SG/intl phones, MRN and labelled EN/AR names. Azure AI Language PII then catches bare names, addresses and other identifiers in the text's language. If Language is on and fails, no model call is made. Translation uses reversible placeholders that stay on our side. | `agents/common/pii.py`, `agents/common/language_pii.py`, `agents/translation.py` | `test_ai_core.py`, `test_language_pii.py`, `test_a2a_translate.py` |
| Harmful or diagnostic output | No-diagnosis lexicon + Azure Content Safety on outputs (fails closed). Number grounding on messages and RAG answers. | `agents/common/guardrails.py`, `agents/common/content_safety.py` | `test_ai_core.py`, `test_rag_learning.py` |
| Excessive agency | Per-step tool scopes enforced on every tool call (`invoke_tool`). Insurer tools only for `navigate` (eligibility, payment options) and `claims`. `MAX_STEPS` per chain. Refusals are logged on the timeline and sent to a person. | `app/contracts.py`, `app/tools.py`, `app/coordinator.py` | `test_a2a_translate.py` |
| Agent identity (A2A) | Every request is signed by `rabt-orchestrator` and every reply by `demo-health-insurance`. Both use HMAC-SHA256 over agent, timestamp, method, path and body (`X-Rabt-Agent`, `X-Rabt-Timestamp`, `X-Rabt-Signature`), with a 300 s freshness window. The insurer refuses unsigned calls (401). Rabt refuses unsigned or mis-signed replies. The secret is generated by Terraform and held as a Container Apps secret. | `agents/common/a2a.py`, `services/insurer_demo/app.py`, `app/insurer_client.py` | `test_a2a_translate.py` |
| Untrusted agent replies | Strict per-skill schemas: unknown fields dropped, enums, ranges, upper-case reason codes, known document ids. Free text is PII-scrubbed and refused if it carries instructions. A reply that fails is **not used**: the case gets `INSURER_REPLY_REJECTED` and a coordinator queue item. | `agents/common/a2a.py`, `app/coordinator.py` | `test_a2a_translate.py` (the `tampered` scenario) |
| Unavailable agent | 5 s timeout. Results in `INSURER_UNAVAILABLE` and a human hand-off; data is never guessed. | `app/insurer_client.py` | `test_a2a_translate.py` |
| Cost / abuse | Per-task `max_tokens`, small-model-first routing, prompt compression, daily token budget, `AI_ENABLED` kill switch. | `agents/common/llm_router.py`, `agents/common/ai_metrics.py` | `test_ai_core.py`, `test_llm_kill_switch.py` |
| Unreviewed prompts | Prompt registry loads only `reviewed: true` prompts. Every call carries `id@version#sha`. | `agents/common/prompts.py` | `test_ai_core.py` |
| Knowledge poisoning | Only physician/supervisor approvals publish KB content. Search filters `approved eq true`. Suggestions are PII-scrubbed. | `agents/rag/kb.py`, `app/main.py` | `test_rag_learning.py` |
| Human identity | Demo personas via `X-Rabt-Persona` with per-route role rules. In a pilot this is replaced by Entra ID / UAE PASS. | `app/auth.py` | `test_demo_auth_roles.py` |
| Audit | Every agent step, A2A exchange (fields, outcome, signature, dropped fields) and refusal is on the case timeline. `/insurer/exchanges` shows the recent A2A log. | `app/ledger.py`, `app/insurer_client.py` | `test_a2a_translate.py` |
| Cloud identity | Managed identities only: the app identity for Key Vault, the KB blob container and AcrPull; the ingestion identity for Search index writes. No keys in images. | `infra/terraform/main.tf` | `terraform test` |

## Demo: a hostile insurer

1. Open the insurer agent page (`terraform output insurer_url`, or `http://localhost:8101` locally) and set the scenario to **tampered**.
2. On the board, find care options for a case.
3. The case timeline shows `A2A · insurer eligibility · rejected`, and the coordinator queue gets "Insurer eligibility reply rejected: check coverage by phone".
4. The web page `/insurer` lists the exchange.
5. Switch the scenario back to **auto**.

Run locally:

```bash
export A2A_SHARED_SECRET=dev-secret-dev-secret-dev-secret-00
PYTHONPATH=services/orchestrator:services:. uv run uvicorn services.insurer_demo.app:app --port 8101 &
INSURER_A2A_URL=http://localhost:8101 PYTHONPATH=services/orchestrator:services:. uv run uvicorn app.main:app --app-dir services/orchestrator --port 8000
```

## Voice and translation

- **Listen (TTS):** the browser's own speech synthesis (`speechSynthesis`, `ar-AE` / `en-US`). Text never leaves the device, and there is no cloud TTS.
- **Live translation (board):** approved EN↔AR phrases are instant. Anything else goes to the small model with names, phones and IDs replaced by placeholders, which are put back after the reply passes the checks. Output is labelled **AI-translated**. With AI off, nothing is invented and the coordinator uses an interpreter.

## Prompt injection: defence in depth

| Layer | Where | What it checks | On failure |
|---|---|---|---|
| 1a. Deny-list | `agents/common/injection.py`, run first in `rag/answer.py` and in the LLM client | Patient text **and** every retrieved KB chunk: "ignore … instructions", "system prompt", "you are now", script tags, exfiltration, Arabic equivalents | Fixed refusal in the patient's language + "talk to a person"; counted as `injection_blocks` |
| 1b. Prompt Shields (app) | `agents/common/content_safety.py`, called through APIM `/contentsafety` before any model call | `userPrompt` = patient text, `documents` = retrieved chunks (indirect injection) | **Fail closed**: if the service errors, no model call, approved template instead; `prompt_shield_blocks` |
| 2. Gateway policy | APIM OpenAI API: `llm-content-safety` with `shield-prompt="true"`, Hate / Sexual / SelfHarm / Violence ≥ 4 (EightSeverityLevels) — `infra/terraform/modules/apim/policies/openai-api.xml.tftpl` | Every prompt that reaches Azure OpenAI, whoever sends it (the app, a script, a leaked key) | 403 from the gateway; the app does not retry on the other model and counts `gateway_safety_blocks` |
| 3. Output checks | `_valid_llm_answer` | Answer must cite a source, use only numbers found in the sources, pass the no-diagnosis lexicon and Content Safety | Extractive approved paragraph instead |

The gateway layer uses its own backend `content-safety-gateway` (Foundry account root URL, APIM managed identity with audience `https://cognitiveservices.azure.com`; Terraform `enable_gateway_content_safety`, default on). The offline benchmark (`benchmark/safety/`, 10 attacks incl. 3 indirect, 4 benign controls) runs in CI; `/benchmark/safety` and the admin page show it next to the live counters.
